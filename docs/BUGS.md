## How continuous monitoring works (how problems become visible)

Three layers; miss one and you get a blind spot:

1. **Server request log** — a middleware in `createApp` records `METHOD path -> status (ms)`,
   marks write operations (POST/PUT/PATCH/DELETE) as "write", and sends >=400 to warn. The `/api/state` poll every 3 seconds is excluded.
2. **Client error beacon** — `web/index.html` installs `error` / `unhandledrejection` / `console.error` listeners
   **before any module loads** and posts to `POST /api/client-log`, which lands in the server log and
   `logs/client-errors.jsonl`. The same error is reported only once, to avoid flooding.
   **Without it, the server knows nothing when a page crashes** — this one was forced into existence by #11.
3. **Behavioural forensics** — under `logs/` there are also `danmaku.jsonl` (danmaku send audit),
   `schedule-history.jsonl` (scheduled task runs) and `live-state.json` (stream-start state baseline).
